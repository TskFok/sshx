# SSHX 独立主机密钥缓存实现计划

**目标：** 首次连接在应用内核验指纹，确认后写入应用数据目录的 `known_hosts` 并继续连接；编辑连接可以清除当前主机和端口的缓存。

**方案：** 沿用现有确认队列和严格重连机制。两种 SSH 后端统一使用应用路径；macOS 显式覆盖系统与用户 SSH 配置中的主机信任来源。以表单中的主机和端口作为缓存身份，清除时保留其他目标。已有密钥变更或撤销仍拒绝连接。

**约束：** 当前 main 分支修改，不新建分支、不自动提交；简体中文文案；不在循环内查询 SQL；不迁移或修改系统 known_hosts。

**技术：** React / TypeScript / Tauri / Rust / OpenSSH / russh。

## 实现与验证

- [x] 共享缓存：应用路径、安全文件创建、按主机端口清除、串行化保存和清除；测试多主机、不同端口、IPv6、散列记录、缺失文件与错误。
- [x] russh：确认与严格验证只接受显式应用路径，无系统路径回退；确认后重新校验再保存。
- [x] OpenSSH：所有连接入口固定应用路径、禁用其他信任来源和免验捷径；原生配置和隔离 sshd 测试验证隔离、保存、变更、清除。
- [x] 编辑界面：清除按钮、目标说明、处理中状态和结果反馈；首次确认说明保存位置；行为测试覆盖请求与异步结果。
- [x] 文档与验收：更新 README，运行前端测试及构建、Rust 测试和本地隔离 sshd 集成测试，独立审查最终改动。

## 审查重点

- SSH 配置中的其他 known_hosts、KnownHostsCommand、DNS 和 localhost/代理免验选项不能建立信任。
- macOS 别名和非默认端口的存储目标与清除目标一致。
- 清除不能丢失其他目标、并发保存不能被覆盖；未确认或落盘失败不能继续连接。
- 用户在清除期间切换编辑对象或目标，不显示旧目标的操作结果。
- 已有信任移至应用缓存后，原来仅由系统记录信任的主机应重新确认。

- 独立审查发现 IPv6 zone 的百分号转义不一致，已通过原生 OpenSSH 配置回归测试修复。额外补充系统会话复用、保存前符号链接复核、端口 0 和字面主机名 none 的回归。
- 系统额外配置的 ProxyJump / ProxyCommand 独立进程认证仍属于代理自身配置；应用目标始终使用独立缓存。README 已明确范围。
