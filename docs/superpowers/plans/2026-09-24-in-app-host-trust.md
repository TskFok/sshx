# SSHX 应用内首次主机信任实现计划

> **For agentic workers:** 使用已确认的会话设计，逐项实现并验证；当前分支工作，不创建分支，不自动提交。

**Goal:** 用户在 SSHX 中核验并保存首次遇到的 SSH 主机指纹，无需打开系统终端；已变更或撤销的密钥继续拒绝。

**Architecture:** 独立的主机信任请求管理器通过全局事件和待处理快照向应用根部弹窗提供主机、端口、算法和 SHA256 指纹。前端只提交请求 ID 与接受/拒绝决定，后端保留被确认的密钥绑定。russh 在真实握手回调中确认并保存；macOS 使用 OpenSSH 本地产生的主机验证信息和原生确认通道，确认后严格验证，保留系统主机记录语义。

**Tech Stack:** React / TypeScript / Tauri 2 / Rust / OpenSSH / russh。

**Spec:** 本会话已确认的方案：首次未知主机显示“取消”“信任并连接”；已信任自动连接；变更和撤销严格拦截。用户已明确要求实现。

## Global Constraints

- 当前分支修改，不创建分支、不提交；禁止循环内 SQL。
- 所有用户文案使用简体中文。
- 信任提示不得来自远端 PTY 或 keyboard-interactive 文本。
- 授权只针对本次显示的主机、端口与具体密钥；过期/重复响应不得生效。
- 未确认、取消、超时、写入失败均停止连接；不覆盖已变更/撤销的记录。
- 普通终端、文件传输及连接测试共用同一信任入口。

## Review Focus

- UI 监听未就绪或卸载、并发请求与异步快照乱序：快照同步且取消安全。
- 用户确认期间服务器密钥或本地记录改变：重新校验，禁止泛化为信任任意新密钥。
- 同一目标不同算法、散列记录、撤销与损坏记录：不得被当作首次未知。
- macOS 自定义 SSH 路径、别名、非标准端口：保留原生 OpenSSH 存储和查找语义。
- 后端请求超时和子进程退出：清理待处理请求与进程，前端不残留弹窗。

## 安装版首次确认失败的回归

- 用户在安装版点击确认后仍被拒绝。捕获实际保存探针日志后确认：该进程输出 CRLF 换行，ASKPASS 的行尾匹配却只接受 LF，导致可选主机记录文件的 ENOENT 被误判为读取错误。
- 使用同一份失败日志复现：原始 CRLF 被拒绝，只替换为 LF 即能确认。修复仅允许 ENOENT 行尾多一个可选 CR，权限错误和其他错误仍拒绝，主机密钥校验策略不变。
- 新增真实助手回归覆盖 LF/CRLF 下的缺失文件和权限错误，并检查拒绝时不消费授权；新增 RSA-only 隔离 SSH 场景，使用完整连接参数与非空主机记录。
- 修复后重新回放实际日志通过，模拟权限错误仍拒绝；Rust 全量 165 通过 / 3 忽略，两个隔离 SSH 集成测试单独运行均通过；独立审查、格式和 diff 检查通过。`pnpm tauri build --bundles app` 成功，已生成包含修复的 SSHX.app。
- 用户确认后，已备份并替换 `/Applications/SSHX.app`，验证安装二进制与修复构建一致，并成功重新启动。用户再次点击「信任并连接」后已确认成功连接。
