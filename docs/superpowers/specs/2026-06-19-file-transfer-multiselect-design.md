# 文件传输多选设计

## 背景

文件传输页面当前一次只能选择一个本地文件或一个远程文件，然后调用现有单文件上传或下载命令。用户需要在同一目录中选择多个文件，并一次加入传输处理。

## 已确认行为

- 点击文件行切换选中或取消选中。
- 点击目录行仍进入目录，不参与多选。
- 搜索、刷新、切换目录后清空当前面板选择，避免保留失效路径。
- 上传或下载按钮根据选择数量启用，并显示选中文件数量。
- 只支持文件多选，目录不加入传输列表。
- 多个文件按用户选中的顺序串行传输。
- 每个文件继续复用现有 `file_transfer_upload` 或 `file_transfer_download` 后端命令。
- 覆盖确认按文件逐个弹出；取消某个文件时跳过该文件并继续处理后续文件。
- 取消传输继续作用于当前正在运行的单个文件。

## 架构

前端把原来的单个 `selectedLocalPath` 和 `selectedRemotePath` 扩展为路径数组。`FilePanel` 接收选中路径集合，文件行点击时由父组件切换数组状态；目录点击保持当前进入目录逻辑。

上传和下载处理函数先解析出当前快照中仍然存在且不是目录的选中文件，再按数组顺序逐个执行现有单文件传输流程。每个文件单独生成 `transferId`、写入 `activeTransfer`、等待后端命令完成并刷新历史。目标目录刷新在批量处理完成后执行一次。

## 错误处理

单个文件传输失败时保留现有错误展示逻辑，并继续刷新历史。用户主动取消覆盖确认只跳过对应文件。用户点击中断时，后端取消当前活动 `transferId`，批量循环在该文件返回后继续清理状态。

## 测试

新增页面静态渲染测试覆盖多选按钮文案与选择计数入口。新增可测试的小型选择工具函数，覆盖：

- 文件路径第一次点击会加入选择。
- 已选文件再次点击会取消选择。
- 多个文件按点击顺序保留。
- 目录或搜索、刷新、切换目录场景由页面逻辑清空选择。
