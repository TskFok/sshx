# 终端滚动条设计

## 背景

终端页面基于 xterm.js。终端已经保留历史缓冲，并由 xterm 的 `.xterm-viewport` 提供原生纵向滚动能力，但 macOS/Tauri WebView 会自动隐藏系统滚动条，用户难以判断当前滚动位置，也不容易发现历史内容可以滚动查看。

## 目标

- 在终端视口右侧提供细窄的纵向滚动条。
- 默认隐藏滚动滑块，鼠标悬停终端视口时显示。
- 保留滚轮、触控板、拖动滑块和键盘滚动等 xterm 原生行为。
- 不改变历史缓冲上限、终端标签切换、壁纸背景和终端尺寸计算。

## 方案

直接为 xterm 原生 `.xterm-viewport` 增加滚动条样式，不引入新的 React 状态或滚动同步逻辑。

- WebKit/Tauri WebView 使用 `::-webkit-scrollbar`、`::-webkit-scrollbar-track` 和 `::-webkit-scrollbar-thumb` 定义尺寸、轨道及滑块。
- 滚动条轨道始终透明；滑块默认透明，在终端视口悬停时显示为中性的半透明颜色，滑块自身悬停时提高对比度。
- 使用细窄宽度和圆角，减少对终端内容区域的视觉干扰。
- 同时设置标准的 `scrollbar-width` 与 `scrollbar-color`，为开发浏览器提供兼容样式。

## 组件与数据流

本功能只修改全局终端样式。xterm 继续维护滚动位置、缓冲区高度和滑块比例；CSS 只控制原生滚动条的外观及悬停状态，不参与会话数据流，也不监听终端输出事件。

## 边界与异常处理

- 缓冲区尚无历史内容时，滑块可能占满轨道，这是浏览器原生行为。
- 不增加 JavaScript 滚动事件监听，避免持续日志输出导致滚动条闪烁或产生额外清理逻辑。
- 动态壁纸模式仍只覆盖视口背景色；滚动条使用独立的中性色，不依赖终端主题背景。
- 不添加横向滚动条样式，现有横向溢出行为保持不变。

## 验证

- 先增加样式契约测试，确认终端视口包含 WebKit 滚动条、默认透明滑块和悬停可见滑块；验证测试在样式实现前按预期失败。
- 实现样式后运行目标测试、全量 `pnpm test` 与 `pnpm build`。
- 在终端产生超过一屏的输出后人工检查：默认状态滑块不可见，悬停终端时可见，滚轮和拖动滑块都能查看历史内容，动态壁纸背景不受影响。
