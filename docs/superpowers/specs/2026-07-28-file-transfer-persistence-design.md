# 文件传输页面持久化与返回列表设计

## 目标

文件传输工作区在切换到应用内其他页面后保持挂载。每个已打开连接独立保留 SSH 会话、目录快照、搜索筛选、已选文件、传输历史以及进行中的传输状态。用户可在顶部标签间切换已打开的文件传输页，也可返回连接选择列表，且这些操作不销毁仍打开的页面实例。

## 方案

采用主布局常驻挂载方案：`MainLayout` 像处理终端页面一样始终渲染一个 `FileTransferWorkspace`，并依据当前 URL 显示或隐藏它。文件传输对应路由仅保留 URL 匹配职责，不再通过 `Outlet` 新建页面实例。

`FileTransferWorkspace` 从 `/file-transfer/:connectionId` 读取当前连接 ID。首次访问某个连接详情 URL 时，将该连接加入打开标签；每个标签对应一个常驻的 `FileTransferPage` 实例，并仅显示活动实例。访问 `/file-transfer` 时显示连接选择列表，已打开标签仍在后台保持挂载。

为保持已有独立页面测试的兼容性，`FileTransferPage` 的连接 ID prop 为可选：工作区提供时优先使用 prop，直接在路由测试中渲染时继续回退到路由参数。

## 交互

文件传输页面顶部增加与终端一致的标签栏：

- 每个标签显示连接图标、连接名称和关闭按钮；
- 点击标签切换到该连接并同步 URL 到 `/file-transfer/:connectionId`；
- 点击关闭按钮或 Shift+单击标签关闭该连接的文件传输页，触发现有组件卸载清理，从而断开对应 SSH 会话；
- 关闭活动标签后切换到最后一个仍打开的标签；没有剩余标签时进入 `/file-transfer` 连接列表；
- 标签栏可水平滚动，名称截断，保留终端页面的视觉层级与交互反馈。

在已选择连接的传输详情页顶部增加“返回列表”按钮：

- 目标地址为 `/file-transfer`；
- 使用左箭头和可见文字，避免纯图标导航；
- 提供明确的无障碍标签与现有按钮一致的键盘焦点样式；
- 返回后展示同一工作区内的连接选择列表，不关闭标签、不清空任何已打开页面的本地或远程目录状态，也不中断正在执行的传输。

再次选择已打开连接时，工作区只激活相应标签，既有连接会话和页面状态保持不变。选择未打开连接时，新增标签并建立该连接会话；不同标签的会话彼此独立，不再因切换标签而取消传输或断开连接。

## 错误处理

持久化与多标签仅改变页面的挂载及显示时机，不改变现有连接、目录读取、认证和传输错误处理。关闭单个标签或应用真正销毁时，对应页面仍执行现有会话断开与事件监听清理。

## 测试

新增或调整测试覆盖：

1. 主布局在离开文件传输路由后仍渲染同一个文件传输工作区，并在非文件传输路由隐藏它；
2. 首次进入连接详情会新建标签，再次进入相同连接只激活既有标签；
3. 标签点击、关闭按钮与 Shift+单击均遵循终端标签的切换/关闭语义；
4. 文件传输详情页渲染“返回列表”按钮，链接指向 `/file-transfer`；
5. 现有无连接 ID 时的连接选择列表行为保持不变；
6. TypeScript 构建与前端测试套件通过。
