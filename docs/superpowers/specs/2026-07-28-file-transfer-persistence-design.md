# 文件传输页面持久化与返回列表设计

## 目标

文件传输页面在切换到应用内其他页面后保持挂载，保留当前 SSH 连接、目录快照、搜索筛选、已选文件、传输历史以及进行中的传输状态。用户在连接详情视图可返回连接选择列表，且此操作不销毁页面实例。

## 方案

采用主布局常驻挂载方案：`MainLayout` 像处理终端页面一样始终渲染一个 `FileTransferPage` 实例，并依据当前 URL 显示或隐藏它。文件传输对应路由仅保留 URL 匹配职责，不再通过 `Outlet` 新建页面实例。

`MainLayout` 从 `/file-transfer/:connectionId` 读取当前连接 ID，并将它传给常驻的文件传输页。访问 `/file-transfer` 时连接 ID 为空，页面显示现有连接选择列表；访问详情 URL 时显示该连接的双栏传输界面。

为保持已有独立页面测试的兼容性，`FileTransferPage` 的连接 ID prop 为可选：主布局提供时优先使用 prop，直接在路由测试中渲染时继续回退到路由参数。

## 交互

在已选择连接的传输详情页顶部增加“返回列表”按钮：

- 目标地址为 `/file-transfer`；
- 使用左箭头和可见文字，避免纯图标导航；
- 提供明确的无障碍标签与现有按钮一致的键盘焦点样式；
- 返回后展示同一页面实例内的连接选择列表，不断开 SSH 会话、不清空本地或远程目录状态，也不中断正在执行的传输。

再次选择同一连接时，既有连接会话和页面状态保持不变。选择不同连接时，维持当前已有的切换语义：取消活动传输、断开旧会话并建立新会话。

## 错误处理

持久化仅改变页面的挂载时机，不改变现有连接、目录读取、认证和传输错误处理。页面真正销毁（应用卸载）时仍执行现有会话断开与事件监听清理。

## 测试

新增或调整测试覆盖：

1. 主布局在离开文件传输路由后仍渲染同一个文件传输页面实例，并在非文件传输路由隐藏它；
2. 文件传输详情页渲染“返回列表”按钮，链接指向 `/file-transfer`；
3. 现有无连接 ID 时的连接选择列表行为保持不变；
4. TypeScript 构建与前端测试套件通过。
