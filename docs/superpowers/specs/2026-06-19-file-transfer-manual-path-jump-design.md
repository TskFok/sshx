# 文件传输手动路径跳转设计

## 背景

文件传输页面当前可以通过点击目录、返回上级、刷新和本地目录选择器切换目录，但本地和远程面板都不能直接输入路径跳转。用户需要在两侧面板中手动输入地址，并快速跳到指定目录。

## 已确认行为

- 本地文件面板和远程文件面板都提供路径输入框和跳转按钮。
- 路径输入框默认显示当前目录，并在目录加载成功后同步为后端返回的规范路径。
- 用户修改路径后按 Enter 或点击“跳转”触发目录加载。
- 加载中禁用对应面板的路径输入和跳转按钮。
- 跳转失败时保留原目录和原快照，显示现有页面错误提示。
- 跳转成功后清空当前面板的搜索词和选中文件，沿用现有切换目录行为。
- 本地路径提交空白时回到后端默认本地目录。
- 远程路径提交空白时不触发跳转。

## 架构

前端在 `FileTransferPage` 中为本地和远程分别维护路径输入状态，并在 `localSnapshot.cwd`、`remoteSnapshot.cwd` 更新后同步输入框。`FilePanel` 继续作为本地和远程共用组件，新增路径输入相关 props：当前路径值、变更回调、提交回调和提交禁用状态。

目录跳转继续复用现有 `loadLocalDir` 和 `loadRemoteDir` 函数，不新增后端命令。成功加载目录后由现有快照更新逻辑刷新文件列表、清空搜索和清空选择；失败时由现有 `connectionError` 显示错误。

## 组件交互

每个文件面板的头部保持标题、返回上级、刷新、当前目录展示和搜索输入。路径输入框放在当前目录展示和搜索输入之间，右侧提供“跳转”按钮。输入框使用明确的 `aria-label`，便于测试和辅助技术识别。

## 错误处理

本地跳转失败通常来自路径不存在、无权限或目标不是目录；远程跳转失败通常来自 SFTP 返回错误。两类错误都进入现有 `connectionError` 展示，不单独增加弹窗。失败不会清空当前目录、搜索词或选中项。

## 测试

新增页面静态渲染测试覆盖：

- 本地文件面板渲染手动路径输入。
- 远程文件面板渲染手动路径输入。
- 两侧都渲染“跳转”操作入口。

已有工具函数和目录加载测试不需要修改，因为跳转复用现有加载函数。
