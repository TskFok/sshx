# 文件传输连接失效快速重连设计

## 目标

当文件传输使用的 SSH 会话连接失败或运行中断开时，在当前页面提供明确的一键重连入口。重连不关闭文件传输标签，不清空本地目录、搜索条件和传输历史；连接恢复后优先回到断线前的远程目录。

## 方案

采用“错误提示内一键重连 + 主动监听会话关闭”的方案。

`FileTransferPage` 单独维护连接生命周期状态，区分初次连接、已连接、已断开和正在重连。连接错误与普通文件操作错误分开判断：首次 SSH/SFTP 初始化失败、收到当前会话的关闭事件，或后端明确返回“会话不存在或已断开”时进入已断开状态；路径不存在、权限不足等目录或传输错误仍只显示错误信息，不提供重连入口。

连接成功后，页面监听与当前会话 ID 对应的 `ssh-close-<sessionId>` 事件。切换到新会话、连接尝试失效或页面卸载时，移除旧会话监听，避免旧事件影响当前页面。

## 交互

连接失效时，页面顶部现有错误提示右侧显示“重新连接”按钮：

- 点击后立即发起新的 SSH 连接；
- 重连期间按钮禁用，显示加载图标和“重新连接中”，防止重复提交；
- 重连成功后清除连接错误和已断开状态；
- 重连失败后保留错误提示与按钮，允许再次尝试；
- 普通路径、权限或文件传输错误不显示该按钮。

页面不会自动重连，避免网络波动期间反复弹出密码、私钥口令或 keyboard-interactive 验证。

## 状态与数据流

页面在远程目录成功加载后记录当前远程目录路径。点击重新连接时：

1. 使旧连接尝试及旧会话事件失效；
2. 若存在进行中的传输，则请求中断该任务并清理页面内的运行状态，不自动重试上传或下载；
3. 保留本地目录快照、搜索条件、传输历史以及断线前的远程目录路径；
4. 建立新 SSH 会话并取得服务器默认远程目录；
5. 若存在断线前目录，优先读取该目录；
6. 原目录读取失败时改为读取服务器默认目录；
7. 默认目录读取成功后完成重连；若默认目录也读取失败，则保持已断开状态并展示错误。

远程文件列表在重连期间不可操作，避免使用已失效的会话发起目录读取或传输。重连成功后以新会话加载的目录快照替换旧快照。

## 并发与清理

继续使用现有连接尝试序号判断迟到结果，只接受当前页面、当前尝试返回的会话。重新连接会产生新的尝试序号，因此旧连接结果即使稍后返回，也会被主动断开且不会覆盖当前状态。

每个文件传输标签仍独立维护自己的连接和重连状态。重连一个标签不会断开或刷新其他标签。页面卸载时移除认证提示监听、会话关闭监听，并断开仍有效的当前会话。

## 错误处理

- 初次连接失败：显示原始错误和“重新连接”按钮。
- 当前会话关闭：显示关闭原因；没有原因时显示统一的“连接已断开”。
- 后端报告会话不存在或已断开：将当前会话标记为失效并显示重连入口。
- 恢复原目录失败：静默尝试服务器默认目录，避免用可恢复的目录变化阻断重连。
- 默认目录也失败：显示最终错误并保留重连入口。
- 重连期间认证取消或失败：结束加载状态并允许再次重试。
- 传输因断线中止：不自动恢复，依赖现有传输历史记录失败结果，避免重复覆盖文件。

## 测试

测试按测试驱动方式补充：

1. 连接状态辅助逻辑只将连接类错误识别为可重连，普通路径或权限错误不显示重连入口；
2. 已断开错误提示渲染“重新连接”按钮，重连中按钮禁用并显示加载状态；
3. 点击按钮产生新的连接尝试，连续点击不会并发建立多个会话；
4. 当前会话关闭事件会进入已断开状态，旧会话关闭事件不会影响新会话；
5. 重连成功后优先读取断线前的远程目录；
6. 原目录读取失败时回退到服务器默认目录；
7. 重连成功后清除错误并恢复远程操作；
8. 重连失败后保留错误与再次重试入口；
9. 现有文件传输前端测试、TypeScript 构建和 Rust 测试保持通过。

## 范围外

- 自动重连或定时退避重试；
- 自动续传或重新执行中断的上传、下载；
- 跨应用重启保存断线前远程目录；
- 修改 SSH 后端连接协议或数据库结构。
